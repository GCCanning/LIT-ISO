## 1. What the game is (canonical, decided 2026-06)

**One game: the Seven-Day-Trial is the FRAME, cozy survival-crafting is the
SUBSTANCE.** (This resolved a prior conflict between two design bibles — doc 15
"cozy" vs doc 17 "trial." Both are now folded into `00_Canonical_Game_Design.md`,
which wins on any conflict.)

The pitch: you are **transmigrated** into a LitRPG world. You create a world +
difficulty, meet **the System** (Stardew-clean UI, player floating in a void), and
get **7 days to prepare** — the **Proving Week**. Every meaningful action is silently
scored. On day 7 you're pulled into the void where the System shows your **rank
(F–S)** and **class choices** scaled to that rank. Higher rank = rarer classes **and
more starting skill points**. Then the long game: a buildable **guild** base,
**affinity**-flavoured magic (ice=slow, fire=burn DoT, poison…), distance-gated
**dungeons** and **towns** (campsite→village→town→city), **overnight travel with
camping/night-danger**, **boat-gated continents**, eventually **horses**, and
**purposeful NPCs**.

Key owner-set rules (full detail + open questions in doc 00):
- **Stats are mechanical:** DEX = faster (move + cooldowns), STR = more damage **+
  jump higher**.
- **Distance = danger + rarity** (mobs, dungeon rank, town tier, loot).
- **Preparation matters:** dungeons require food/water/potions/sharpening
  stones/mana stones; travel may need overnight camping.
- **Night is dangerous:** stronger mobs actively hunt you; you're safe only inside a
  **campfire's radius**, where you **sleep in a tent** to skip night. Camp gear has a
  **rarity tier**; under-geared in a too-strong area → chance a mob ignores the
  "wards," attacks, and **damages your camp gear**.
- **Guild = base:** build your own, **rank it up to enlarge the interior**, lay it out
  by **painting the grid with tiles from inventory** (the BiomeSketch paint tool);
  **craft stations get bonuses inside the guild** that scale with rank/level.

## 3. Current build state (what works vs. what's stubbed)

**Canonical scene:** `Assets/Scenes/IsoCoreFoundation.unity`, built entirely on
`Awake` by **`FoundationBootstrap`** (the only constructor of world/player/inventory).
**Canonical assembly:** `IsoCore.Foundation` (isolated; no reference to legacy
`Assembly-CSharp`). Editor validators pass (FoundationValidator 34/34;
FoundationIntegratedSliceValidator 132/136 across recent slices). `dotnet build
IsoCore.Foundation.csproj` is clean.

**Working / playable now:**
- Procedural isometric terrain, multiple biomes; WASD move with world-query collision.
- Harvesting (durability bars, held-LMB), farming (till→plant→grow→harvest), building/
  placement (ghost preview, placed solids block movement).
- Crafting incl. **timed + fueled** recipes; per-station crafting panel + progress
  (furnace smelting, tannery shipped — see `WORKSTATION_ROADMAP.md`).
- Mobs (pooled wander/spawn/despawn), tool durability + held-tool swing.
- **Dungeons:** distance-tiered portals, deterministic rooms/corridors, rewards/
  completion, persistent portal history (save v8). **Pocket interiors:** tavern,
  library (enterable).
- **LitRPG layer:** stats/XP/progression runtime, 7 Callings, ~13 skills, 5 starter
  quests, abilities/spells with elemental affinity ranks, and a **Trial scoring data
  spine** (Evidence/Marks/XP channels/Titles/Classes/Professions) — validated.
- **UI:** uGUI HUD + tabbed character panel (Inventory/Crafting/Skills/Spells/
  Character/Journal/Map/Settings/System), day/night clock, minimap + fullscreen map,
  notifications, ability wheel, options/settings, loading screen, quit-autosave.
- **Menu flow:** welcome → world select (seed/difficulty/JSON saves) → calling/
  character creation → launches Foundation scene via `ConfigureLaunch`;
  transmigration intro cutscene; animated/cinematic menu background.

**Stubbed / missing / in-flux (the gap to the vision):**
- **Trial runtime not closed:** scored actions → rank → class-offer generation → bonus
  skill points is still a **TODO** (the ceremony UI exists; bind the runtime).
- **Owner mechanics not built:** night-danger + campfire-ward + tent sleep; guild-as-
  paintable-rankable-base; dungeon prep-consumables gate; affinity element→effect +
  usage/drop growth + rank ceiling; STR→jump; town tiers + market services; purposeful
  NPCs; boats/continents; horses.
- **Save/load:** piecemeal (dungeon v8, map v10, explored cells); unified
  `FoundationSaveData` is **WIP**.
- **Art:** core still renders as placeholder cubes in places; promoting/wiring the
  PixelLab set per biome is in flight (organic worldgen work).
- Weather visuals, towns/economy/NPCs: concept-only (not extracted from legacy).

## 6. Current refinement priorities (owner, 2026-06)

The near-term focus is **refining what exists**, not new vision features. In order:

1. **Biomes** — generation rules + per-biome look. Build on the in-flight "organic
   world generator" (6-layer, Whittaker climate table, elevation/lapse-rate gating,
   adjacency rules, blend bands — see `WORLDGEN_RULES_PROPOSAL.md`) and wire the
   PixelLab tile/prop pools per biome by semantic role. Touches `IsoTerrainSampler.cs`
   and `BiomeDefinition.cs`.
2. **Shaders** — sprite/lighting shaders for depth & mood (there's a depth/contact-
   shadow helper + `SpriteAmbient` shader already; extend).
3. **Lighting** — day/night, ambient, campfire/glow, atmosphere.
4. **Game feel** — moment-to-moment polish across the above.
5. **Build `.bat` resilience** — `Tools/BuildGame.bat` / `BuildScript.cs` /
   `GameBuilder.cs` must build a working `.exe` **even after new scenes/scripts/assets
   are added**, so the owner can always test the real game. Auto-include canonical
   scenes (`MenuScene`, `IsoCoreFoundation`), validate scenes exist, fail loudly (no
   silent half-build), write `build_info.txt`. **Small/medium; do early — it unblocks
   play-testing everything else.**
6. **Dungeon edge-collision (owner spec, verbatim intent):** dungeon/instance edge
   tiles bordering the void must collide at the **outer edge of the tile**, not its
   center. Picture an **invisible wall standing at the tile edge that faces the void,
   rising infinitely upward**, wrapping the **entire perimeter of edge tiles that
   touch nothing**. The player (who stands in the middle of a tile) must be stopped
   exactly at that border — never allowed to drift over the lip into the void.
   Implement by marking the void-facing edges of the walkable region as solid/occupied
   in the per-cell occupancy layer (Foundation already has occupancy + world-query
   collision — this is generator data, not new physics). Pairs with the planned
   "void rework" (walkable tiles only + void particles). Touches the dungeon/instance
   generators under `Assets/Scripts/IsoCoreFoundation/`.

## 8. Git workflow

There are **no ownership lanes** — you own the entire codebase. (`AGENTS.md` still
describes a Codex/Claude split and per-lane scene ownership; that is obsolete. The
*invariants* in `AGENTS.md` still hold — see §7.)

- `git pull --rebase` before starting.
- Branch off `main` (e.g. `feat/<task>`); **never commit to `main`; never
  force-push.**
- Small, single-purpose commits; commit `.meta` files alongside their assets.
- Binaries (png/wav/fbx/ttf/…) are **Git LFS** (`.gitattributes`); only commit them
  where git-lfs is installed (§5 caveat). Never commit `Library/`, `.dotnet/`, or
  builds.
- Recommended cleanup: when convenient, update `AGENTS.md` to delete the lane/two-
  agent sections so the contract matches reality.
